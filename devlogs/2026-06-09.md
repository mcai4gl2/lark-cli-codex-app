## Slack Gateway MVP

### Problem / Goal
- Implement Phase 2 from `slack-migration.md`: add a Slack Socket Mode gateway MVP while preserving the existing shared inbound, agent, and desktop paths.
- Follow the repository requirement to use Docker-based Go formatting, tests, and build verification.

### Problems Encountered
- Docker `go build` initially failed with `error obtaining VCS status: exit status 128`; reran the build after marking `/work` as a safe git directory inside the container.

### Key Design Decisions
- Added a small direct Slack Web API client instead of introducing a larger SDK dependency for the MVP.
- Kept Slack code in `internal/slack` and injected the Slack messenger into existing inbound, agent, and desktop queue paths.
- Used `.slack/` defaults for Slack event logs and desktop tasks so existing `.lark/` state is untouched.

### Solution / Implementation
- Added Slack config/env bindings for app token, bot token, bot user ID, gateway, and agent settings.
- Added Slack Web API support for `chat.postMessage`, `auth.test`, and `apps.connections.open`.
- Added Slack event normalization for `app_mention` and `message.im`, including bot/self-message filtering, mention stripping, thread selection, and neutral event persistence.
- Added `lark slack gateway serve` with agent, event-log, auto-reply, workspace, and desktop-worker flags.
- Added focused tests for config, Web API calls, event normalization, desktop queue routing, and command registration.
