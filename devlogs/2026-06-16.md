## Local Summarizer Integration (plan/20260616_local-summarize-integration)

### Problem / Goal
- Implement optional compression of growing Slack thread transcripts fed to Codex by summarizing long outbound (LLM reply) records via a local Gemma 3 1B model over HTTP.
- Controlled by `slack.local_summarizer.*` config flags; fully optional with silent fallback on any error.
- No new dependencies — use only `net/http`.

### Problems Encountered
- Go is not installed locally; discovered this mid-task. Resolved by running all build/test verification inside the `golang:1.24` Docker image used in CI (`docker run --rm -v "$(pwd)":/workspace -w /workspace golang:1.24 ...`).
- The existing `context_test.go` is in package `slackmemory` (internal), while the plan's new summarizer tests are in `slackmemory_test` (external). Could not append to the same file due to package name conflict — created a separate `context_summarize_test.go` file instead.
- Docker build fails with `VCS stamping` error inside container; resolved with `-buildvcs=false`.

### Key Design Decisions
- `Summarizer` interface is defined in the `slackmemory` package (not in `internal/summarizer`) to avoid an import cycle. `*summarizer.Client` satisfies this interface by duck typing.
- Summarization only applies to `directionOutbound` records — inbound (user) messages are never compressed, preserving full fidelity of user intent in prompts.
- On any summarizer error or empty summary result, the original uncompressed record is used silently — callers never see summarizer errors propagate.
- `SummarizeMinChars` defaults to 300 if not set, preventing unnecessary HTTP calls for short replies.
- Quality integration test (`quality_test.go`) uses `//go:build integration` tag and auto-skips if `LOCAL_SUMMARIZER_URL` is not set or the service is unreachable.

### Solution / Implementation
- **Task 0**: Created `internal/summarizer/quality_test.go` — integration test that walks real `SLACK_MEMORY_ROOT` event files, feeds outbound records to the live model, and asserts compression ratio ≤ 0.85 and zero 5-gram repetitions.
- **Task 1**: Created `internal/summarizer/client.go` — `Summarizer` interface + `Client` struct with `Summarize` (POST `/v1/summarize`) and `Available` (GET `/health`) methods. Created unit tests with `httptest` stubs.
- **Task 2**: Added `LocalSummarizer` struct to `Config.Slack` in `config.go`, with 5 defaults, 5 env bindings (`SLACK_LOCAL_SUMMARIZER_*`), and 5 getter functions.
- **Task 3**: Extended `ContextOptions`/`TranscriptOptions` with `Summarizer` and `SummarizeMinChars` fields; added summarization loop in `BuildRecentTranscript` guarded by `directionOutbound`; added 4 new unit tests in `context_summarize_test.go`.
- **Task 4**: Added `LocalSummarizer *summarizer.Client` and `LocalSummarizerMinChars int` to `slack.Config`; extended `memoryPromptProvider` with matching fields and passed them through `BuildPromptContext`.
- **Task 5**: Wired config getters into `cmd/slack.go` `slackGatewayServeCmd`; instantiates `*summarizer.Client` when enabled; logs `local_summarizer_enabled/url/min_chars` at startup.
- **Task 6**: Added `local_summarizer:` block to `config.example.yaml` with comments for all 5 knobs.
