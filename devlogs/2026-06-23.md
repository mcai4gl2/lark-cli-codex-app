## Codex Session Resume — Phase 1 Implementation (plan/20260623_long-running-codex-feasibility)

### Problem / Goal
- Replace the fire-and-forget `codex exec` model with persistent Codex sessions that map 1:1 to Slack threads, so follow-up messages resume the same session instead of spawning a new process with reconstructed context.
- The current transcript-replay approach degrades as conversations grow: context gets truncated, Codex loses tool-call history and file state from prior turns, and long outbound replies are summarized lossy.
- Opt-in via `slack.agent.session_resume: true` config flag. Requires `memory` to be enabled (for the `.state/` directory).

### Problems Encountered
- Go is not installed on the dev machine, so build and test verification could not be run. This was a known issue from prior tasks (2026-06-16). Verification should use `docker run --rm -v "$(pwd)":/workspace -w /workspace golang:1.24 go test -buildvcs=false ./internal/agent/...`.
- The `Backend` interface return type change (`string` → `BackendResult`) is a breaking change to all implementers. Both `CodexBackend` and `AgyBackend` needed updates in the same changeset. `AgyBackend` returns `BackendResult{Text: ...}` with an empty `SessionID` since it has no session concept.

### Key Design Decisions
- **`--json` + `StdoutPipe` streaming instead of `CombinedOutput`**: The `--json` flag causes Codex to emit JSONL events to stdout. We need to parse the `thread.started` event for the `thread_id` while the process is still running. Changed from `cmd.CombinedOutput()` to `cmd.StdoutPipe()` + `bufio.Scanner`, with stderr captured separately via `strings.Builder`.
- **Prompt switching on resume**: When resuming a session, only the raw `entry.MessageText` is sent — no system prompt, no memory context, no transcript replay. Codex already has the full conversation history including tool calls and file diffs. Memory context is still injected for new sessions.
- **Fallback on resume failure**: If `codex exec resume` fails (stale session, corrupt state), the runner logs the error, clears the session mapping, and retries as a new session with full prompt context. This prevents a broken session from permanently blocking a thread.
- **SessionStore follows RecoveryStore pattern**: Same mutex + atomic-rename JSON file approach (`os.CreateTemp` → write → `os.Rename`). Stored at `<memory-root>/.state/sessions.json` alongside `recover-state.json`.
- **Session cleanup on thread removal**: When `RecoveryStore.RemoveThread()` fires (thread expired or closed by tick reaction), the corresponding session mapping is also removed via a new `removeSessionForRecoveryKey` helper.

### Solution / Implementation
- **SessionStore** (`internal/agent/session.go`): Thread-safe JSON file store mapping `SessionKey{Provider, ChannelID, ThreadTS}` → Codex `thread_id`. Methods: `Lookup`, `Put`, `Remove`.
- **BackendResult** (`internal/agent/backend.go`): New return type carrying both `Text` and `SessionID`. `Backend` interface updated, `BackendRequest` gains `SessionID` field.
- **CodexBackend.Execute** (`internal/agent/codex.go`): Builds `codex exec resume <id> --json ...` when `SessionID` is set, otherwise `codex exec --json -C <workspace> ...`. Parses stdout JSONL for `thread.started` event via `parseThreadID()`. Returns `BackendResult` with extracted `thread_id`.
- **Runner.execute** (`internal/agent/codex.go`): Session lookup → prompt switching → execute → fallback on resume error → store new session ID. Extracted `buildFullPrompt` helper and `sessionKeyFromEntry` utility.
- **Config** (`internal/config/config.go`): `SessionResume bool` added to both `Agent` and `Slack.Agent` structs, with defaults (`false`), env bindings (`LARK_AGENT_SESSION_RESUME`, `SLACK_AGENT_SESSION_RESUME`), and getters.
- **Gateway wiring** (`internal/slack/gateway.go`): Creates `SessionStore` in `NewGateway` when `SessionResume` is enabled; cleans up sessions on thread expiry/close.
- **CLI wiring** (`internal/cmd/slack.go`): Passes `SessionResume` through `DefaultAgentConfigInput`; adds `agent_session_resume` to startup JSON.
- **Tests** (`internal/agent/session_test.go`, `internal/agent/codex_test.go`): SessionStore CRUD + persistence + nil-safety; CodexBackend `--json` parsing and `SessionID` extraction; resume flow with session persistence; fallback on stale session; `sessionKeyFromEntry` edge cases.
